# Quantum-inspired AST relation retrieval for repository code completion

**Date:** 2026-09-27  
**Decision:** Pilot an AST-relation-factorized fidelity scorer; only add cross-relation phase interference if the simpler factorized scorer beats its classical controls. Do not claim either will beat AlignCoder until matched completion experiments show it.  
**Constraints:** No knowledge distillation, no pairwise examples/loss, no quantum-hardware or quantum-advantage claim.

## Executive finding

The useful new hypothesis is **where phase is placed**. The notebook learns a phase for every coordinate of a pooled UniXcoder embedding. I recommend instead aligning factors with code semantics—identifier/signature, AST role/scope, AST-GR edge/path, and dependency/call/import evidence—and testing (1) factorized log-fidelity, then (2) coherent interference across those factors. This directly uses the user's AST chunking and AST-GR relation data, is interpretable, and can be trained with pointwise BCE without KD or pairwise construction.

Quantum-inspired phase/interference is a plausible interaction parameterization, not established code-retrieval evidence. QIEPSM is TREC retrieval; QINM is ad-hoc text retrieval; Q-Interference is language-model attention; complex embeddings are sentence classification. The closest fidelity-head study finds modest/competitive retrieval results and reports that, with the backbone frozen, its quantum-inspired head trails a classical compression head. **No reviewed source tests phase-aware scoring on repository-level code completion.** So this is a falsifiable experiment, not a promised win. [QIEPSM](https://arxiv.org/abs/2501.04591), [QINM/SIGIR](https://doi.org/10.1145/3397271.3401070), [Q-Interference](https://arxiv.org/abs/2608.17288), [ACL complex embeddings](https://aclanthology.org/W18-3006/).

### Scorer math

Retriever default: `microsoft/unixcoder-base`. For each of its 768 hidden coordinates, the code maps

```text
theta(h) = pi/2 * (1 + tanh(h))
phi(h)   = pi + pi * tanh(Linear(h))
|psi_i>  = cos(theta_i/2)|0> + exp(i*phi_i) sin(theta_i/2)|1>
```

It compares query and candidate with product-state fidelity, accumulated as a sum of per-dimension log overlaps. The learned phase projection is a dense 768×768 map with 590,592 parameters including bias. This is a classical nonlinear similarity/kernel head—not a quantum circuit, not quantum hardware, and not a demonstrated quantum advantage. The phase varies by embedding coordinate; the notebook does not assign phase to AST relation types.

### Training loop and generator

The active path is **online hard-reward retriever training**, not KD: it uses `microsoft/unixcoder-base` as retriever and, by default, frozen `deepseek-ai/deepseek-coder-1.3b-base` to score the gold target continuation. Each epoch mines candidates with the current retriever, runs generator target-NLL scoring, assigns the lowest-loss candidate as the winner, and trains the retriever with cross entropy. It re-mines/re-scores after each epoch. There is no pairwise example generation. For the QIEPSM scorers the engine rejects the advertised soft/hybrid modes, so the chosen hard loss is the operative one. The default utility weighting and its language/token-index bugs are recorded in S01.

The notebook therefore does **not** implement the no-distillation AST-GR method proposed here: its supervision comes from generator target-NLL winners, and its chunks/prefixes are legacy/synthetic rather than the user's AST units and AST-GR labels. It also incurs repeated generator-scoring cost after retriever updates—the simpler fixed-pool AST-GR pilot avoids that.

## Notebook validity audit

All code cells are unexecuted and have no saved outputs; there is no observed phase result. The main audit findings are:

- The cell-0 recipe selects checkpoints by macro EM/ES on a fixed CrossCodeEval **TEST** subset. The active `build_validation` indeed reads `cceval/{python,java}/test.parquet`, and those same rows are used at scheduled epochs to select `best_crosscodeeval`. If run as configured, the selected score is test-contaminated; it is not an untouched test estimate.
- The launcher runs only the online scorer. It does not execute a matched cosine/fixed-phase/learned-phase comparison on the same candidate and reward rows. The separately generated controlled script is not the active path and does not expose the learned-phase scorer in its CLI.
- Candidate chunks and synthetic completion examples are not AST-based. This notebook cannot establish how the phase head interacts with the user's AST chunker/AST-GR training.
- Prompt construction lets longer cross-file candidates consume more prompt budget and shrink the local current-file prefix, confounding candidate utility.
- In mixed Python/Java reward scoring, the active engine passes the first pool's language into the identifier-weight function for every example. Its flattened-token index also applies the “first token” weight only to the first flattened target token in a batch.
- `--benchmark-limit` is accepted, but the benchmark subprocess uses `--limit 0`; changing that wrapper option does not constrain the saved validation JSONL evaluation.
- `SMOKE=True` deliberately runs one epoch; evaluation starts at epoch 2. The notebook comments correctly say smoke has no benchmark validation, so that run cannot supply a best checkpoint or evidence of completion gains.

## Proposed direction: AST relation-factorized phase retrieval

### Candidate/evidence representation

Keep AST chunks as the atomic candidates and union independent candidate sources: BM25/identifier, dense UniXcoder, AST-symbol, and dependency/graph expansion. Deduplicate by stable AST node/span ID. Preserve retrieval-pool recall as a separate ceiling metric.

For each query-candidate pair form semantic evidence factors:

1. visible identifier/API/signature match;
2. AST node role, type, and scope relation;
3. AST-GR edge type/path relation;
4. import/call/dependency relation;
5. optional dense semantic similarity.

Every query-side feature must be available from the visible prefix/repository at inference; hidden target tokens can only define training labels, not candidate generation or inference features.

### Scorer: simplest first, interference second

For factor `r`, encode query/candidate evidence into a normalized two-level complex state and compute fidelity `F_r(q,c)`. First scorer:

```text
s_fact(q,c) = sum_r w_r * log(epsilon + F_r(q,c))
```

This is a weighted product kernel. It tests whether AST/identifier/dependency factors provide useful conjunctive evidence; it may over-penalize one weak factor, so compare clipped/normalized log-fidelity as a stability ablation.

Only if this works, test coherent phase interaction across factors:

```text
a_r = softplus(g_r(features_r, q, c))
phi_r = pi * tanh(h_r(features_r, q, c))
z(q,c) = sum_r a_r * exp(i * phi_r)
s_int(q,c) = alpha * log(epsilon + |z(q,c)|^2) + b
```

Its intensity includes cross terms `2*a_r*a_t*cos(phi_r-phi_t)`: e.g. a matching API identifier and call-edge can reinforce, while incompatible AST role can suppress. This is a classical feature computation; implement with sine/cosine features, not a quantum simulator. A real-valued MLP over the exact same factors is the essential control.

### Training loss: concrete, no KD, no pairwise

**First pilot main loss:** if the current AST-GR artifact has independent binary query-candidate labels, train one query-candidate at a time with class-balanced `BCEWithLogitsLoss`. First inspect its actual label schema, positive definition, negative sampling, and leakage rules—the AST-GR implementation itself was not audited here. Preserve graded/multilabel semantics rather than silently thresholding. This pointwise structural supervision needs no LLM reward model, teacher token distributions, KL, RL, or pairwise data.

If the first pilot improves AST-GR ranking but not completion, a separate task-utility objective can be tested without KD or pairwise ranking. Let retriever probabilities be `pi_i = softmax(s(q,c_i)/T)` and let the frozen **downstream generator** assign scalar gold-continuation NLL `ell_i = -log P_G(y | visible_prefix,c_i)`. Then:

```text
L_completion = -log sum_i pi_i * exp(-ell_i)
```

This is a marginal likelihood of the actual gold continuation, not KL distillation; no teacher token-distribution target or chosen/rejected pairs are formed. It still uses generator-derived likelihoods, so it is not teacher-free; for a fixed candidate pool, `ell_i` can be scored once and cached instead of dynamically re-mined each epoch. Also, the single-candidate mixture must be validated against the actual top-K prompt used at inference. Keep it as a second-stage ablation, not the first scorer test.

## Minimal experiment and controls

### Stage A — isolate the scorer cheaply

Freeze the same candidate pool, AST chunks, AST-GR labels, query tokens, prompt budget, and train/dev repositories for every row:

| Variant | What it isolates |
|---|---|
| UniXcoder cosine | Dense baseline |
| Calibrated additive lexical+dense+AST+dependency | Strong simple hybrid |
| Parameter-matched real MLP over identical factors | Generic nonlinear-capacity control |
| Relation-factorized fidelity, fixed then learned phases | AST-relation fidelity hypothesis |
| Cross-factor interference, with phase-off/amplitude-only ablations | Constructive/destructive cross-view interaction |
| Notebook per-hidden-dimension learned-phase log fidelity | Reproduction of the supplied idea |

Train all with the same pointwise AST-GR BCE and budget. If generator utility is tested, freeze the candidate pool and generator-NLL cache across scorer variants.

### Stage B — validate actual completion

First report pool recall before reranking and AST-GR Recall@K/precision/nDCG/MRR after reranking. Then evaluate end-to-end against a matched AlignCoder configuration: same repository split, same generator (the notebook default is DeepSeek-Coder-1.3B only if it is also the downstream benchmark generator), prompt/decoding, candidate budget, and local-prefix token count. Use repository-disjoint train/dev/test manifests, at least three seeds and paired uncertainty estimates. Dev selects checkpoints; test is evaluated once. Report EM/ES, no-retrieval/harmful-context behavior, latency, and memory.

### Sanity checks and run order

1. Unit-test the product-fidelity/Bloch formula and log-vs-product rank equivalence; confirm phase-off reduces to its stated fixed-phase control.
2. Overfit one tiny AST-GR batch, verify the metric code on hand-constructed candidate rankings, and inspect false positives/negatives.
3. On a repository-disjoint development split only, run a small pilot (e.g., 100–200 queries per language if available) with the frozen common candidate pool and all scorer controls.
4. If the mechanism survives, run the full dev completion evaluation; only then run the untouched test once. Test size and seed count should be powered from the project's benchmark variance; use at least 3 seeds for this first screening.
5. Keep the optional cached-generator-likelihood objective as a separate, later run; it changes the supervision as well as the scorer and must not be mixed into the first mechanism test.

### Go/no-go

Advance the phase method only if it beats cosine **and** the parameter-matched real MLP on fixed-pool AST-GR ranking, then improves end-to-end EM/ES over matched AlignCoder across seeds without material latency/memory regression. If MLP matches it, keep the simpler classical scorer. If label metrics rise but completion does not, the method has not met the target.

## Evidence status and adversarial conclusions

- **High confidence:** the active notebook uses online frozen-generator hard target-NLL feedback and its checkpoint selection reads CrossCodeEval TEST; the code cells have no saved outputs (S01).
- **Moderate confidence:** phase/interference can parameterize interactions and has non-code retrieval/NLP precedents (S02–S05). This supports an experiment, not a code-completion performance expectation.
- **High confidence:** phase/fidelity alone is not established as a standalone retrieval upgrade; QIEPSM reports modest/non-universal results, and the reviewed QI retrieval studies do not compare modern code retrievers (S02–S06).
- **Insufficient evidence:** that any quantum-inspired score can beat AlignCoder. A classical MLP may capture the same useful nonlinearity; AST-GR can improve structural relevance without completion utility; multi-path candidate recall can explain gains independently of scoring; phase may suppress useful lexical evidence.

The strongest counterargument is that a classical hybrid AST retriever is more likely to yield gains than a quantum-inspired head. This is why the proposed study starts with a fixed-pool low-cost scorer ablation and keeps a hard “classical MLP matches → stop phase” rule.
